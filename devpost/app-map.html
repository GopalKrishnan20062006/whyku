Whyku · code tour reference

How a verified hint reaches the board

Whyku helps Sudoku players understand a supported next move. Python checks the grid and proves the deduction; Gemini may arrange approved explanation clauses, while FastAPI renders the factual wording. React displays the returned record and explanation.

Follow one hint in the code

This is a reference route through the implementation; it is not a record of an interactive code tour.

  1. React action: frontend/src/App.jsx, requestHint and advanceHint start the ladder and request the reasoning. SudokuBoard renders the backend candidate/evidence records, and enterDigit clears old evidence and refreshes analysis.
  2. HTTP boundary: frontend/src/api.js, getHint and getExplanation send only the puzzle ID and current grid. backend/app/main.py, routes in create_app, validate and re-analyze each request.
  3. Proof and wording: backend/app/sudoku/engine.py, analyze_grid and backend/app/sudoku/singles.py, find_singles/validate_deduction, produce and verify the move. backend/app/explanations/service.py, ExplanationService.explain, checks selected clause IDs and falls back to the deterministic template.

To change this, start here

  • Hint-stage wording and evidence display: frontend/src/App.jsx, hintNudge, EvidenceSummary, and the ladder markup.
  • Candidate rules and deduction evidence: backend/app/sudoku/candidates.py and backend/app/sudoku/singles.py; add a regression case in backend/tests/test_engine.py.
  • Approved explanation content and fallback: backend/app/explanations/renderer.py; provider behavior: backend/app/explanations/gemini.py.

A practice to reuse

Whyku’s spec gave the solver and explanation provider separate responsibilities, then tests checked deductions and provider failures independently. On another AI-assisted project, write down which component is allowed to decide a result, define the data crossing that boundary, and test the decision without the language model before adding generated wording.

Run Whyku locally (template mode needs no API key)

Start these from the repository root in two PowerShell terminals. Requires Python 3.12+, Node.js 22.12+, and npm.

cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:EXPLANATION_PROVIDER = "template"
uvicorn app.main:app --reload
cd frontend
npm ci
npm run dev

Open the Vite URL printed in the frontend terminal. For live Gemini mode, configure GEMINI_API_KEY in the ignored backend/.env; never place it in frontend files.
